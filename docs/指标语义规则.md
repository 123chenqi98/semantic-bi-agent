# 指标语义规则表

本项目的核心知识库。Agent 在理解问题、生成 SQL 和校验结果时，**必须严格遵循以下定义**。

---

## 一、全局口径总规则（所有指标共享）

| 规则项 | 约定 |
|--------|------|
| 支付状态过滤 | 默认仅统计 `pay_status = '已支付'` 的订单明细；**已退款、未支付均不计入** |
| 时间范围默认 | 若问题无明确时间，默认取"最近一个完整自然月"（例如今天 2026-08-19，则默认 2026-07-01 ~ 2026-07-31） |
| 空值处理 | 指标计算结果为空或 0 时，输出 0 并注明"无符合条件数据" |
| 金额单位 | 默认单位为"元"，大额时可自动格式化为"万元"保留 2 位小数 |
| 比率/占比输出 | 统一格式化为百分比（保留 2 位小数，如 23.45%） |

## 二、核心指标（5 个，MVP 必做）

### 指标 1：销售额（sales_amount）

| 项目 | 内容 |
|------|------|
| **指标名称** | 销售额 |
| **英文标识** | sales_amount |
| **业务定义** | 在统计周期内，客户已实际支付的订单商品折后总金额（不含退款和未支付） |
| **计算公式** | SUM( order_item.amount ) WHERE pay_status = '已支付' |
| **同义词/别名** | 成交额、营收、总收入、销售总额、GMV（注：GMV 在本口径下等同于销售额，不包含未支付与退款） |
| **容易被混淆的口径** | ❌ 把已退款和未支付算进去 → 得到的是"下单金额"而非"销售额"<br>❌ 用 unit_price * quantity 不加 discount → 得到"原价销售额"而非"实际销售额" |
| **时间范围规则** | 支持日/周/月/季/年；环比/同比需明确对比周期 |
| **支持分析的维度** | 时间（date.year/quarter/month/week）、区域（customer.region/city）、品类（product.category/sub_category）、会员等级（customer.member_level）、渠道（order_item.channel）、品牌（product.brand） |
| **结果解释模板** | "{时间范围} 内的销售额为 {数值} 元，较 {对比周期} {上升/下降} {幅度}。其中贡献最大的维度为 {维度_1}，占比 {占比_1}。" |

---

### 指标 2：订单量（order_count）

| 项目 | 内容 |
|------|------|
| **指标名称** | 订单量 |
| **英文标识** | order_count |
| **业务定义** | 在统计周期内，状态为"已支付"的**独立订单个数**（同一 order_id 的多行明细只计 1 单） |
| **计算公式** | COUNT(DISTINCT order_id) WHERE pay_status = '已支付' |
| **同义词/别名** | 订单数、成单数、交易量、单量 |
| **容易被混淆的口径** | ❌ 用 COUNT(*) 统计 order_item 行数 → 得到"订单行数"（同一订单多件商品会重复计数）<br>❌ 未去重 DISTINCT → 同订单多商品会被算成多单 |
| **时间范围规则** | 支持日/周/月/季/年 |
| **支持分析的维度** | 时间、区域、会员等级、渠道 |
| **结果解释模板** | "{时间范围} 内的订单量为 {数值} 单。平均每日约 {日均} 单，{渠道} 渠道贡献最大，占比 {占比}。" |

---

### 指标 3：客单价（aov）

| 项目 | 内容 |
|------|------|
| **指标名称** | 客单价 |
| **英文标识** | aov（Average Order Value） |
| **业务定义** | 每一笔已支付订单的平均消费金额 |
| **计算公式** | 销售额 / 订单量 = SUM(amount) / COUNT(DISTINCT order_id) WHERE pay_status='已支付' |
| **同义词/别名** | 单均价、平均客单价、每单均价、单笔均价 |
| **容易被混淆的口径** | ❌ 按客户数平均（那是"人均消费"或 ARPU，不是客单价）<br>❌ 分母用 COUNT(*) 行数而不是 DISTINCT 订单 → 同订单多商品会导致客单价被低估 |
| **时间范围规则** | 支持日/周/月/季/年；但时间过短（小时级）波动大，建议最小粒度"日" |
| **支持分析的维度** | 时间、区域、会员等级、渠道、品类（注意：按品类时需以"该品类出现在订单中的金额"计算，同一订单跨品类时分母仍为订单数） |
| **结果解释模板** | "{时间范围} 内客单价为 {数值} 元，较上一周期 {上升/下降} {幅度}。高客单价主要来自 {维度} 群体。" |

---

### 指标 4：新客数（new_customer_count）

| 项目 | 内容 |
|------|------|
| **指标名称** | 新客数 |
| **英文标识** | new_customer_count |
| **业务定义** | 在统计周期内**首次发生支付行为**的客户数量（首单时间落在该周期内）。以"实际支付"而非"注册"或"下单"为准。 |
| **计算公式** | COUNT(DISTINCT customer_id) <br>WHERE pay_status='已支付' <br>AND customer_id 的 MIN(order_date) ∈ [统计时间范围] |
| **同义词/别名** | 新增客户数、新增付费客户、首单客户数 |
| **容易被混淆的口径** | ❌ 按注册日期统计（那是"新增注册数"，不代表有消费）<br>❌ 按下单日期统计但未过滤已支付 → 包含未支付客户会虚高<br>❌ 按"注册日期在周期内且有消费"统计 → 老客户注册但首单延迟会漏算 |
| **时间范围规则** | 通常支持月/季/年；日级可能过小 |
| **支持分析的维度** | 时间、区域、会员等级（首单时的等级）、渠道（首单渠道） |
| **结果解释模板** | "{时间范围} 内新增付费客户 {数值} 人，较同期 {上升/下降} {幅度}。主要来源区域为 {区域}。" |

---

### 指标 5：复购率（repurchase_rate）

| 项目 | 内容 |
|------|------|
| **指标名称** | 复购率 |
| **英文标识** | repurchase_rate |
| **业务定义** | 在统计周期内，发生过 **2 次及以上已支付订单** 的客户数占该周期内有支付行为客户总数的比例 |
| **计算公式** | （周期内订单数 ≥ 2 的付费客户数） / （周期内全部付费客户数） × 100% <br>分子分母都只统计 pay_status='已支付' |
| **同义词/别名** | 复购占比、回头客比例、重复购买率 |
| **容易被混淆的口径** | ❌ 用订单数的重复比（如 ≥2 单的订单数 / 总订单数）→ 错，应该是客户维度<br>❌ 跨周期统计（如"历史累计复购"）→ 那是"存量复购率"，不是"周期内复购率"，需明确说明<br>❌ 未过滤 pay_status → 退款/未支付订单可能误算为复购 |
| **时间范围规则** | 建议最小粒度"月"；周级及以下数据波动剧烈，参考价值有限 |
| **支持分析的维度** | 时间、区域、会员等级、渠道（首单渠道）、品类偏好（按客户首单品类） |
| **结果解释模板** | "{时间范围} 内复购率为 {百分比}，即每 100 位付费客户中有 {整数部分} 位购买超过 1 次。{维度} 群体复购表现最好。" |

## 三、扩展指标（3 个，MVP 之后可选）

### 指标 6：活跃客户数（active_customer_count）

| 项目 | 内容 |
|------|------|
| **指标名称** | 活跃客户数 |
| **英文标识** | active_customer_count |
| **业务定义** | 在统计周期内至少发生 1 次已支付行为的独立客户数 |
| **计算公式** | COUNT(DISTINCT customer_id) WHERE pay_status='已支付' |
| **同义词/别名** | 活跃用户数、付费客户数、消费人数 |
| **容易被混淆的口径** | ❌ 用"登录但未消费的客户" → 那是"活跃登录数"，不是经营分析口径 |
| **时间范围规则** | 日/周/月/季（常用"月活跃客户 MAU"） |
| **支持维度** | 时间、区域、会员等级、渠道 |
| **结果解释模板** | "{时间范围} 内活跃付费客户数为 {数值} 人。" |

### 指标 7：商品转化率（product_conversion_rate）

*注：在本项目数据集中没有"曝光/点击"数据，此处定义为"订单维度转化率"——被下单的商品数占上架在售商品总数的比例。*

| 项目 | 内容 |
|------|------|
| **指标名称** | 商品动销率（即商品转化率） |
| **英文标识** | product_conversion_rate |
| **业务定义** | 统计周期内至少产生 1 笔已支付订单的在售商品数，占全部在售商品总数的比例 |
| **计算公式** | COUNT(DISTINCT product_id 有过已支付订单) / COUNT(DISTINCT product_id WHERE status='在售') × 100% |
| **同义词/别名** | 动销率、上架售出率、商品覆盖率 |
| **容易被混淆的口径** | ❌ 分母包含"下架"商品 → 会导致分母过大、转化率虚低<br>❌ 分子未过滤已支付 → 虚高 |
| **时间范围规则** | 月/季 |
| **支持维度** | 时间、一级品类、品牌 |
| **结果解释模板** | "{时间范围} 内商品动销率为 {百分比}，{品类} 表现最佳。" |

---

### 指标 8：区域销售占比（region_sales_share）

| 项目 | 内容 |
|------|------|
| **指标名称** | 区域销售占比 |
| **英文标识** | region_sales_share |
| **业务定义** | 在统计周期内，某区域的销售额占全公司总销售额的百分比 |
| **计算公式** | SUM(amount) WHERE region=X AND pay_status='已支付' / SUM(amount) WHERE pay_status='已支付' × 100% |
| **同义词/别名** | 区域贡献占比、区域销售构成、销售区域分布 |
| **容易被混淆的口径** | ❌ 分子用订单量而不是销售额 → 那是"区域订单占比"，不是销售占比<br>❌ 分母只算部分区域合计 → 总和不等于 100% |
| **时间范围规则** | 日/周/月/季/年 |
| **支持维度** | 时间（必须）、在"区域"基础上可再叠加 渠道 / 品类 的双维度占比 |
| **结果解释模板** | "{时间范围} 内销售额区域分布为：{区域1} {占比1}、{区域2} {占比2} ...；其中 Top1 为 {Top1区域}，占比 {Top1占比}。" |

## 五、时间范围常用语义（供 Agent 识别）

| 自然语言表述 | 对应范围（假设今天 = 2026-07-01，匹配数据集截止 2026-06-30） |
|-------------|--------------------------|
| 今天 | 2026-07-01 |
| 昨天 | 2026-06-30 |
| 近7天 / 最近一周 | 2026-06-25 ~ 2026-07-01 |
| 近30天 / 最近一个月 | 2026-06-02 ~ 2026-07-01 |
| 本月 / 当月 | 2026-07-01 ~ 2026-07-01（今日）或 2026-07-01 ~ 2026-07-31（完整月，看语境） |
| 上月 / 上个月 | 2026-06-01 ~ 2026-06-30（完整自然月，**默认口径**） |
| 本季度 | 2026-07-01 ~ 2026-09-30（未完结用至今日） |
| 上季度 | 2026-04-01 ~ 2026-06-30 |
| 今年 | 2026-01-01 ~ 2026-07-01（或至年底） |
| 去年 | 2025-01-01 ~ 2025-12-31 |
| 同期 / 同比 | 去年同一时间段（如 2026-07 vs 2025-07） |
| 环比 | 上一个同粒度周期（如 2026-07 vs 2026-06） |
| 默认（问题没给时间） | 最近一个完整自然月（2026-06-01 ~ 2026-06-30） |
