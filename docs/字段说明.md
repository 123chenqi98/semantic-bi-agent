# 字段说明文档

## 一、数据来源说明

本项目采用**公开零售场景 + 自建模拟数据**的方式构建实验数据集，覆盖 2025-01-01 至 2026-06-30 共 18 个月的经营数据。

数据特点：
- 客户（customer）：2000 名注册客户，覆盖 7 大区域、会员分层
- 商品（product）：200 款商品，分 5 大类 25 小类，含成本与售价
- 日期（date）：546 天的时间维表，含年/季/月/周/节假日等维度
- 订单明细（order_item）：1.8 万条订单行，含渠道、支付状态、折扣等

所有数据通过 `src/data_processing/generate_sample_data.py` 脚本生成（随机种子 42，可复现）。

---

## 二、表关系总览（星型模型）

```
                    ┌──────────────┐
                    │    date      │  时间维表
                    │  (date_id)   │
                    └──────┬───────┘
                           │ 1
                           │
                           │ N
┌──────────────┐     ┌─────▼─────────┐      ┌──────────────┐
│   customer   │     │  order_item   │      │   product    │
│(customer_id) │1───N│(事实表/无主键)│N─────1│(product_id) │
└──────────────┘     └───────────────┘      └──────────────┘
```

**说明**：
- `order_item` 为事实表，粒度为"订单中一个商品一行"
- `order_id` 表示同一订单（可包含多个商品行），非唯一主键
- 三张维表分别通过 `customer_id` / `product_id` / `date_id` 与事实表关联
- 数据仓库建模风格：星型模型，便于经营分析聚合

## 三、各表字段说明

### 3.1 customer（客户维表）
| 字段名 | 类型 | 含义 | 取值/备注 |
|--------|------|------|-----------|
| customer_id | INT | 客户唯一ID | **主键**，1~2000 |
| customer_name | VARCHAR | 客户姓名 | 随机中文名 |
| gender | VARCHAR | 性别 | 男 / 女 |
| age | INT | 年龄 | 18~60 |
| region | VARCHAR | 所在区域 | 华东/华北/华南/华中/西南/西北/东北（7 个） |
| city | VARCHAR | 所在城市 | 对应区域下的 6 个代表城市之一 |
| member_level | VARCHAR | 会员等级 | 普通/银卡/金卡/钻石（占比约 50%/30%/15%/5%） |
| register_date | DATE | 注册日期 | 2025-01-01 ~ 2026-03-10 |

### 3.2 product（商品维表）
| 字段名 | 类型 | 含义 | 取值/备注 |
|--------|------|------|-----------|
| product_id | INT | 商品唯一ID | **主键**，1~200 |
| product_name | VARCHAR | 商品名称 | 格式："{子品类}{ID}号" |
| category | VARCHAR | 一级品类 | 电子产品 / 家居用品 / 服装配饰 / 食品饮料 / 美妆个护（5 个） |
| sub_category | VARCHAR | 二级子品类 | 每大类下 5 个小类，共 25 个 |
| brand | VARCHAR | 品牌 | 品牌A~E、国货精品 |
| cost_price | DECIMAL(10,2) | 成本价 | 约为售价的 35%~65% |
| sale_price | DECIMAL(10,2) | 标准售价 | 19.9 / 49.9 / 99 / 199 / 399 / 699 / 1299 / 2999 / 5999 档位 |
| status | VARCHAR | 商品状态 | 在售 / 下架（9:1） |

**品类结构**：
| 一级品类 | 二级子品类 |
|---------|-----------|
| 电子产品 | 手机、电脑、耳机、平板、智能手表 |
| 家居用品 | 床上用品、厨房用具、收纳、灯具、家具 |
| 服装配饰 | 男装、女装、鞋靴、箱包、首饰 |
| 食品饮料 | 零食、饮料、生鲜、酒水、调味品 |
| 美妆个护 | 护肤、彩妆、香水、洗护、男士护理 |

### 3.3 date（时间维表）
| 字段名 | 类型 | 含义 | 取值/备注 |
|--------|------|------|-----------|
| date_id | INT | 日期ID | **主键**，连续递增 |
| date | DATE | 具体日期 | 2025-01-01 ~ 2026-06-30 |
| year | INT | 年份 | 2025 / 2026 |
| month | INT | 月份 | 1~12 |
| quarter | INT | 季度 | 1~4 |
| season_name | VARCHAR | 季度名 | 如 "2025Q1" |
| month_name | VARCHAR | 月份名 | 如 "2025-01" |
| week_of_year | INT | 周序号 | ISO 周编号（1~53） |
| weekday | INT | 周几 | 周一=1，周日=7 |
| is_weekend | TINYINT | 是否周末 | 1=是，0=否（周六周日） |
| is_month_end | TINYINT | 是否月末 | 1=当月最后一天，0=否 |

### 3.4 order_item（订单明细表 / 事实表）
| 字段名 | 类型 | 含义 | 取值/备注 |
|--------|------|------|-----------|
| order_id | INT | 订单号 | **同订单号的多行属于同一订单** |
| date_id | INT | 下单日期ID | 外键 → date.date_id |
| order_date | DATE | 下单日期 | 冗余字段，便于直接查询；与 date_id 一致 |
| customer_id | INT | 客户ID | 外键 → customer.customer_id；**保证下单日期 ≥ 客户注册日期** |
| product_id | INT | 商品ID | 外键 → product.product_id |
| quantity | INT | 购买数量 | 1~5（多数为 1 件） |
| unit_price | DECIMAL(10,2) | 成交单价（折扣前） | 取自 product.sale_price |
| discount | DECIMAL(3,2) | 折扣率 | 1.00 表示无折扣；其余如 0.9 = 9 折 |
| amount | DECIMAL(10,2) | 行金额（折后实付） | = unit_price × quantity × discount |
| channel | VARCHAR | 销售渠道 | 线上APP(40%) / 线下门店(25%) / 小程序(20%) / 第三方平台(15%) |
| pay_status | VARCHAR | 支付状态 | 已支付(85%) / 已退款(10%) / 未支付(5%) |

## 四、主键 / 外键 / 关联关系

| 主表 | 主键 | 子表 | 外键 | 关系 |
|------|------|------|------|------|
| customer | customer_id | order_item | customer_id | 1 : N（一个客户多笔订单） |
| product | product_id | order_item | product_id | 1 : N（一个商品被多次购买） |
| date | date_id | order_item | date_id | 1 : N（一天多笔订单） |

## 五、数据使用建议

1. **SQL 口径的关键开关**：
   - 销售额统计通常只算 `pay_status = '已支付'` 的行；退款和未支付不计入
   - 新客定义通常取 `register_date` 与首单日期结合判断（见指标语义规则表）
   - 复购率计算需要按客户分组统计其订单数量

2. **常见分析组合**：
   - 维度 × 指标：`region` / `category` / `member_level` / `channel` / `month_name` × 销售额/订单量/客单价
   - 时间粒度：日 / 周 / 月 / 季 / 年

3. **数据质量规则**（后续结果校验模块可用）：
   - 同一 `order_id` 下多行的 `order_date`、`customer_id` 必须一致
   - `amount = round(unit_price * quantity * discount, 2)`
   - 订单日期不早于注册日期
