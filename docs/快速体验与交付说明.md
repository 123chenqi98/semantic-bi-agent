# 快速体验与交付说明

> 面向首次试用、答辩演示与交付验收的一份说明书。目标：**3 分钟跑通核心价值，10 分钟看完成熟度边界**。
> 技术部署细节见 [部署与企业BI接入说明.md](./部署与企业BI接入说明.md)，本文只讲「怎么用、能信什么、不能信什么」。

---

## 1. 这个系统能做什么

一句话：**用自然语言完成经营数据分析，且全程「口径可见、SQL 可控、结果可信」。**

- **智能问数**：输入业务问题（如「上个月各渠道销售额」），系统先理解需求、生成 SQL 草案，**你确认后才执行查询**（确认前绝不跑 SQL，只读模式）。
- **分析工作台**：结果不是一句聊天回复，而是结构化工作台——执行摘要、数据来源与口径、SQL 依据（可复制）、核心发现、图表、结果表（可导出 CSV）、风险提醒、下一步动作。
- **结果可复用**：可继续追问（如「按品类拆分」）、修改口径重问、一键把结果生成图表、导出表格。
- **企业 BI 接入准备**：已内置风神 BI 企业级接入层（配置 / 校验 / 请求 / 映射 / 状态五层），凭证与通道就绪，真实取数待白名单联调。
- **可运维**：系统状态面板（版本 / 运行模式 / 数据源五态 / 审计摘要）、结构化审计日志、统一链路日志。

## 2. 推荐体验路径（约 3 分钟）

首页「分析工作台」即引导页，建议按此顺序体验：

| 步骤 | 操作 | 看点 |
|------|------|------|
| ① 看状态 | 打开首页，看顶部三张状态卡 | 当前数据源「真实可用」、风神 BI「已配置·待联调」、模型状态一眼可见 |
| ② 发起问数 | 在「精选示例」点一个**业务问数**问题（如「上个月各渠道的销售额和订单量是多少？」） | 自动进入对话，先出需求理解 + SQL 草案 |
| ③ 确认执行 | 在草案卡片点「确认执行」 | 体现「确认前不执行」的安全闸门 |
| ④ 看工作台 | 查看结构化结果 | 摘要 / 口径 / **SQL 依据（可复制）** / 发现 / 图表 / 结果表 |
| ⑤ 继续分析 | 点「基于结果生成图表」或追问「按品类拆分」、导出 CSV | 体现结果可复用，而非一次性回答 |
| ⑥ 看趋势 | 回到首页点一个**趋势分析**示例（如「近6个月的订单量变化趋势」） | 时间序列自动配图、环比/波动发现 |
| ⑦ 看可运维 | 进入「系统设置 → 系统状态与审计」 | 数据源五态列表、最近审计事件表、权限边界说明 |

> **给答辩/面试的一句话演示脚本**：「我不用写 SQL，先问业务问题 → 系统把口径和 SQL 摊开给我确认 → 确认后只读执行 → 结果是一个可追问、可导出、可出图、带可信度判定的分析工作台，而不是一段聊天文本。」

## 3. 哪些是真实能力，哪些是演示 / 待联调

### ✅ 真实可用（本地即可依赖）

- 本地零售数据集（retail.db，4 张表 21,064 行，覆盖 2025-01 ~ 2026-06）上的**真实查询执行**；
- 语义层 Text-to-SQL、指标口径注入、时间语义修正、SQL 自修复重试、题库兜底；
- 分阶段确认（需求 → SQL 草案 → 确认 → 执行）、只读保护；
- 分析工作台七分区、CSV 导出、追问、结果二次出图；
- 数据源五态状态机、系统状态面板、审计日志（JSONL 落盘 + 接口查询）。

> 说明：配置了真实 LLM Key 时 SQL 由大模型生成（当前模型可能触发限流，限流时自动降级为**内置语义题库/维度模板**生成 SQL，但对本地数据库的查询执行始终真实）。SQL 来源在结果页与审计中如实标注。

### 🟡 演示态（链路真实，数据为模拟）

- **风神 BI 取数结果**：需求识别与 SQL 草案是真实能力；但真实取数需账号开通 MCP 邀测白名单，开通前最终数据**回退为明确标注的 Mock**（结果页黄色横幅 + 审计「Mock/兜底」标识），**绝不冒充真实企业数据**。
- 未配置 LLM Key 时：SQL 出自题库/模板（审计如实记录），查询仍真实执行。

### 🔧 待联调 / 预留（不伪造）

- 风神 MCP **真实取数**：协议、鉴权、SSE 传输、方言转译、容错均已实现并在内网实测握手，待白名单开通 + 内网环境；
- **用户登录与权限体系**：当前为单用户版，无登录；审计字段 `user_id/tenant_id` 与 4 个权限点已预留，**尚未实现权限拦截**；
- 审计日志平台对接（现为 JSONL 文件，可接 ELK/Loki）。

## 4. 如何启动系统

```bash
# 1. 后端（端口 5001）
cd 项目根目录
cp .env.example .env          # 可选：填入 LLM_API_KEY 启用真实大模型；不填也能完整跑通（题库兜底）
python3 -m src.demo.app_backend

# 2. 前端（端口 5173）
cd web
cp .env.example .env          # 一般无需修改；VITE_BACKEND_URL 仅在前后端分离部署时填写
npm install
npm run dev
# 浏览器打开 http://localhost:5173
```

生产 / Docker 部署见 [部署与企业BI接入说明.md](./部署与企业BI接入说明.md) 第 4~6 节（含 docker-compose、nginx、gunicorn）。

启动后后端控制台会打印**统一启动摘要**（版本、运行模式、数据源五态、审计目录），并在每次问数时打印 `[BI][时间][阶段] ...` 链路日志。

## 5. 如何配置数据源与验证企业 BI 状态

**本地数据源（currentLocal）**：默认即用，无需配置，状态恒为「真实可用」。

**风神 BI（fengshenBi）**：
1. 在项目根 `.env` 配置 `FENGSHEN_BI_WORKSPACE_ID`、`FENGSHEN_BI_CLIENT_ID/CLIENT_SECRET`、`FENGSHEN_BI_PROXY_USER` 等（见 `.env.example` 注释）；
   或在前端「系统设置 → 数据源管理 → 风神 BI 授权配置」表单填写（后端内存托管，密钥脱敏、不进浏览器）。
2. 到「企业 BI」页或设置页点「**测试连接**」验证。
3. 观察状态徽标（五态）：
   - `未配置` / `Mock 演示`：未填凭证，纯演示；
   - `已配置 · 待联调`：凭证已填但本进程尚未真实验证，或最近真实调用失败（白名单未开通 / 网络不通）——取数回退 Mock；
   - `凭证已验证` / `真实可用`：真实握手 / 取数成功。

**命令行验证**：
```bash
curl http://localhost:5001/api/system/status     # 一次看全：服务 / 模型 / 数据源五态 / 审计
curl http://localhost:5001/api/enterprise-bi/status | python3 -m json.tool
```

## 6. 如何完成一次完整分析流程

1. 首页点示例问题（或在输入框自由提问）；
2. 系统返回**需求理解**（识别的指标、时间范围、维度、口径假设）与 **SQL 草案**；
3. 核对无误后点「确认执行」（需要澄清时会先给澄清问题）；
4. 进入**分析工作台**：读执行摘要 → 看数据来源与口径 → 看 SQL 依据（可复制）→ 看核心发现与图表 → 查结果表；
5. 继续工作：点追问建议（如「按渠道拆分」）、「修改口径重问」、「导出 CSV」、「基于结果生成图表」；
6. 全程在「系统设置 → 系统状态与审计」可查到本次请求的数据源、是否经确认、SQL 来源、是否命中兜底、成功与否。

## 7. 已知限制（诚实清单）

- 数据集为**零售演示数据**，用于方法验证与口径核对，不代表真实企业经营数据；
- 风神 BI **真实取数尚未打通**（待 MCP 白名单 + 内网），当前取数回退 Mock；
- **无登录与多租户权限**，审计 user_id 固定 anonymous，权限点仅预留未拦截；
- LLM 走第三方大模型，限流时降级题库，极端复杂问题的 SQL 可能不如题库精确；
- 审计为 JSONL 文件 + 进程内缓冲，多 worker 下缓冲按进程独立（以落盘文件为准），未接集中式日志平台；
- 域名 ICP 备案审查通过前不加公网 DNS 解析。

## 8. 一页速查：怎么判断当前是不是真实模式

| 你想确认的 | 看哪里 |
|------------|--------|
| 后端是否在线 | 首页状态卡 / `/api/health` |
| 当前数据源与连接态 | 首页三卡、设置页「系统状态与审计」、`/api/system/status` 的 `datasource.items[].connection_status` |
| 风神是真实还是待联调 | 徽标「真实可用」=本进程真实取数成功过；「已配置·待联调」=未验证或失败回退 |
| 本次结果是不是 Mock | 结果页黄色横幅 / 审计表「取数」列「Mock/兜底」徽标 |
| SQL 是模型还是题库生成 | 结果页/审计 `sql_source`：`llm`/`semantic-llm` 为模型，其余为题库/模板兜底 |
| 系统版本与运行时长 | 设置页「后端服务」卡或 `/api/system/status` 的 `backend.version` |
