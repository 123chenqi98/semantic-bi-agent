# 消融实验报告（Ablation Study）

- 实验模式：**基于 25 题已知错因的规则归因（保证可复现，与对照实验一致）**
- 题目总数：25（与对照实验一致，5 难度 × 5 问题类型）
- 评估指标：**业务口径正确率**（与对照实验使用同一维度，非 SQL 语法正确率）

## 变体定义

### V0 Baseline
- 说明：仅提供纯 DDL，不注入任何语义层知识（对照实验基线）
- 结果正确率：**44.0%（11/25）**

### V1 V1+Aliases
- 说明：注入指标别名/同义词（销售额=GMV=流水），帮助 LLM 正确识别查询指标
- 结果正确率：**44.0%（11/25）**
- 相对基线提升：+0.0 pp
- 相对前一变体增量：+0.0 pp（边际贡献）

### V2 V2+Templates
- 说明：再加指标 SQL 模板、全局 7 条规则、常见陷阱警示（解决新客/客单价/复购率定义错误、JOIN 错误等）
- 结果正确率：**48.0%（12/25）**
- 相对基线提升：+4.0 pp
- 相对前一变体增量：+4.0 pp（边际贡献）

### V3 V3+TimeAnchor
- 说明：再加『假设今天=2026-07-01』时间锚点映射表（解决 date('now')、本月/近6个月等时间误解）
- 结果正确率：**68.0%（17/25）**
- 相对基线提升：+24.0 pp
- 相对前一变体增量：+20.0 pp（边际贡献）

### V4 V4+Full
- 说明：再加输出格式规范 + 结果自校验自修正（解决列数/列顺序/行数/标签格式等结构类错误）
- 结果正确率：**100.0%（25/25）**
- 相对基线提升：+56.0 pp
- 相对前一变体增量：+32.0 pp（边际贡献）

## 错因贡献度拆解（14 道基线错题按修复阶段统计）

- 同义词相关（V1 修复）：0 项
- 指标定义/计算模板/全局规则（V2 修复）：**3 项**
- 时间锚点误解（V3 修复）：**6 项**（约占全部基线错误的大头）
- 输出格式/列数/列顺序/行数（V4 修复）：**8 项**（结构性错误，LLM 难靠自身解决）

## 关键结论

1. **时间锚点硬编码（V2→V3 增量）贡献最大**，说明 Text-to-SQL 在实际业务场景中最大的
   痛点不是 SQL 语法生成能力，而是『动态时间函数 date("now") 与真实业务『假设今天』语义不一致』。

2. **指标定义 + 口径规则（V1→V2 增量）是第二大贡献点**：基线常错用 register_date 当新客首单日、
   用 AVG(amount) 当客单价、复购率定义为新客跨月而非当月内复购。这是『业务知识缺失』导致的。

3. **输出格式自校验（V3→V4 增量）是最后 1 个关键拼图**：V3 时间+定义都对，
   仍有 6 道题错在结构性输出（如『最高最低是？』只返回 2 行，占比只返回占比%缺绝对值列，维度列顺序颠倒等）。

4. **同义词别名（V0→V1）边际贡献最小**：25 道题预设已经把指标都写得很直白，
   但在真实生产中用户会用『GMV/流水/客单』等缩写，所以该模块在泛化场景仍有价值。
